# きいてるﾁｬﾝ

「きいてるﾁｬﾝ」は、話の内容を理解せず、声量・発話時間・沈黙時間だけから話の切れ目を見つけて自然にうなずく、製品版M5Stack StackChan専用のローカルArduinoアプリです。待機中は正面・直立で静止し、声を検出するとサーボを動かさず「ん？」という傾聴顔へ切り替えます。ステレオマイクの左右方向は診断表示だけに使い、誤方向を避けるため横サーボへ直接接続しません。通常版ではカメラを初期化・撮影・解析しません。顔は製品版公式ファームのデフォルトスキンを土台にし、頭を前後になでると公式同様のHappy表情・ハート・照れ頬で応えます。音声認識、録音保存、Wi-Fi/BLE、クラウド、生成AI、外部サーバーは使いません。PCMは保存・送信しません。

待機中と傾聴中はサーボを動かさず、画面内だけで約5.2秒周期の自然な瞬き、4回に1回の二度瞬き、上下1pxの呼吸、小さな視線移動、傾聴顔のわずかな拡大を行います。うなずき完了後はHappy顔、ゆっくり瞬き、通常顔の順で約0.75秒の余韻を作ります。睡眠時と起床時は約0.9秒かけて目の開き方を段階的に変え、寝顔の右上では太い線の`Z`が1個、2個、3個の順にゆっくり循環します。なでなで終了時は、通常顔へ直接戻る場合もハートが約1.2秒かけて上へ抜けながら小さく消えます。LEDは発話中に緑、なでなで中に柔らかな桃色で固定点灯し、それ以外の通常状態では消灯します。画面外バッファが確保できない場合は、ちらつきを避けるため自動的に静止画へ切り替わります。

## 対象ハードウェア

- M5Stack製品版 StackChan、SKU K151
- StackChan Core（ESP32-S3）搭載品
- 内蔵デュアルマイク、LCD、上下・横サーボ、頭部3ゾーンタッチ、RGB LEDのみを使用
- 一般的な自作版、Core2版、CoreS3 Lite版は対象外

公式Arduino資料に従い、PlatformIOではボードID `m5stack-cores3`（M5CoreS3）としてビルドします。

## 必要なソフト

- Windows、macOSまたはLinuxのPC
- [Visual Studio Code](https://code.visualstudio.com/)
- VS Code拡張機能 [PlatformIO IDE](https://platformio.org/install/ide?install=vscode)
- データ通信対応USB-Cケーブル
- 工場出荷ファーム復元用の[M5Burner](https://docs.m5stack.com/en/download)
- 自動テストを実行する場合のみ、PATHから呼べるGCC/G++（ファームウェアのビルドには不要）

依存ライブラリとArduino-ESP32環境は`platformio.ini`に固定済みです。初回ビルド時だけインターネット接続が必要です。実行時のネットワーク通信はありません。

## VS CodeとPlatformIOで開く

1. VS Codeを起動します。
2. `File` → `Open Folder...`から、この`hearing-chan`フォルダーを選びます。
3. PlatformIOの初期化と依存ダウンロードが終わるまで待ちます。
4. VS Code下部に`Default (hearing-chan)`または`stackchan_k151`環境が表示されることを確認します。

## ビルド

PlatformIOのチェックマーク（Build）を押すか、PlatformIO CLIで次を実行します。

```powershell
pio run -e stackchan_k151
```

生成物は`.pio/build/stackchan_k151/firmware.bin`です。

開発・編集・ビルド対象は`C:\dev\hearing-chan`だけです。OneDrive側の同名フォルダーは使用しないでください。ビルドは中間ファイル競合を避けるためプロジェクト側で1ジョブに固定しています。初回は公式ライブラリ全体をコンパイルするため時間がかかりますが、途中でVS Codeを閉じたり`.pio`を削除したりせず完了を待ってください。

純粋ロジックのテストは次のとおりです。

```powershell
pio test -e native
```

## USB接続と書き込み

> **安全のため、原則として台座側のUSB-Cポートを使用してください。** Core側ポートもデータ通信できますが、M5Stack公式案内でも予期しないモーター動作を避けるため台座側が推奨されています。可動部の周囲を空け、StackChanを安定した机に置いてください。

カスタムファームを書き込むと、現在の工場出荷ファームは上書きされます。必要な設定があれば先に控えてください。

1. StackChanを安定した場所に置き、台座側USB-CポートとPCを接続します。
2. 電源ボタンを1回押します。
3. ポートが見えない場合は、RSTボタンを約2～3秒長押しし、内部の緑LEDが点灯したら離してダウンロードモードにします。
4. PlatformIOのUpload（右矢印）を押します。CLIでは、実際のポート名に置き換えて次を実行します。

```powershell
pio run -e stackchan_k151 -t upload --upload-port COM5
```

このリポジトリの検証では実機への書き込みを行いません。

## シリアルモニター

PlatformIOのプラグ形アイコン（Serial Monitor）を押すか、次を実行します。書き込みと同じポートを指定してください。

```powershell
pio device monitor --baud 115200 --port COM5
```

状態遷移、較正開始・完了、頭部スワイプ、音の推定方向、初期化エラーが表示されます。音声サンプルそのものは表示されません。

## 初回起動時の確認

1. 顔と可動部に手を触れず、周囲を空けて電源を入れます。
2. 通常顔が表示され、上下軸が安全ホーム、横軸が正面0度へゆっくり移動することを確認します。
3. ホーム到達とサーボ音抑制が終わると、約1.5秒の起動時ノイズ較正が始まります。シリアルに完了と出るまで静かに待ちます。
4. 頭部を前から後ろ、または後ろから前へゆっくりなで、Happy表情・ハート・照れ頬と小さな上向き動作を確認します。手を離して約2秒後に元の表情と姿勢へ戻ります。
5. 待機中に正面・直立のまま静止することを確認します。普通の声で話し、発話中は傾聴顔と浅いうなずき、話し終えて約0.6秒後に深いうなずきが1回だけ出ることを確認します。
6. 画面の短いタップでデバッグ表示を出し、状態、左右の`L`/`R`音量、推定方向`DIR`、`LEVEL`、`NOISE`、しきい値、直前発話時間を確認します。
7. StackChanの正面、画面左、画面右から順に話し、`DIR`を診断します。`DIR`が逆または不安定でも音方向では首を動かさないのが正常です。左右設定を無理に追い込まず、記録だけ残します。
8. 画面を長押しすると「しずかにしてね」と表示され、約3秒で音環境を再較正します。サーボ動作中またはなでなで中の長押しは安全のため無視されます。

必ず[実機調整ガイド](docs/tuning-guide.md)の順番で確認してください。最初から大きな角度へ変更しないでください。

## 反応ルール

| 条件 | 反応 |
|---|---|
| 200 ms未満 | 物音として反応しない |
| 発話中 | 約1.6秒間隔で20→16.8→20度の浅いうなずき |
| 200 ms以上の発話終了 | 回数・深さ・速さ・保持時間を安全範囲内で変えたランダムうなずき |

開始には120 msの継続、終了には600 msの沈黙が必要です。発話時間や大声から反応を分類せず、成立した発話の終了時にハードウェア乱数から安全な動作計画を作ります。回数は1回約70%・2回約30%、最下点は浅め11～13度が35%、中間8～10度が45%、深め5～7度が20%です。深めは必ず1回に限定します。下降速度は浅・中185～215、深め185～200、復帰速度165～190です。保持時間も制限範囲内で変化させ、直前と完全に同じ計画は避けます。反応後のクールダウンと最低反応間隔は維持します。60秒発話がなければ寝顔と寝姿勢になり、声量上昇で起きます。

## なでなで操作

画面ではなく、製品版K151の頭部上面にある3ゾーンタッチセンサーを操作します。`StackChan-BSP`が公開する`getIntensities()`の生値を使い、前↔中央または中央↔後の隣接2ゾーンを順になでるか、頭部のどこかへ40～400 msだけ触れて完全に離すとHappy顔へ入ります。長押しは単発タップとして扱いません。なで移動時間の初期範囲は15～1200 ms、センサー境界の無接触許容は80 msです。短い接触中に隣接2ゾーンを順に通った場合は、なでなでを優先します。

製品版公式`HeadPetModifier`のHappy表情、ハート、照れ頬、離して2秒後の復帰を維持しています。なでている間は大きさを変えない1個のハートが小さく上下し、照れ頬は最初から左右3本ずつ表示します。確定した単発タップでは同じ1個のハートが最初に一度だけ大きく弾み、サーボは動かしません。なでなでだけ、本作品の安全要件に合わせた小さな上向き動作を行います。手を離すと既存の上へ抜ける余韻へつながります。最初の頭部接触から、最後の接触またはリリース後900 msまで、マイクの発話判定・ノイズ学習・左右方向判定を抑制して打音を声として扱いません。

## マイクしきい値の調整

主な値は`include/AppConfig.h`の`audio`名前空間にあります。

- 感度が低い: `kStartThresholdRatio`または`kStartThresholdMargin`を少し下げます。
- 環境音に反応しすぎる: 上の2値を少し上げます。
- 話の途中で切れる: `listener::kSpeechEndHoldMs`を少し増やします。
- 机の打音に反応する: `listener::kSpeechStartHoldMs`または`kMinimumSpeechMs`を増やします。
- サーボ音に再反応する: `motion::kServoSoundSuppressionAfterMs`を増やします。

一度に1項目だけ変更し、短いタップのデバッグ値で変化を確認してください。環境が大きく変わったら、画面を長押しして再較正します。

### 左右方向の診断

デュアルマイクの方向推定値は`DIR:L`（画面左）、`C`（中央）、`R`（画面右）、`?`（不確か）です。音量差だけでなく、左右へ音が届く時刻の差を最大±3サンプルで比較します。実機では反射や声の成分による揺れが確認されたため、`audio_direction::kEnableSoundServoTracking = false`を製品設定とし、方向推定値を横サーボへ接続しません。既存の多数決ロジックは純粋ロジックテスト用に保持しています。

`DIR`が常に逆でも現段階では`kSwapStereoChannels`を変更する必要はありません。複数環境の記録を基に調整します。

## サーボ角度と速度の調整

`include/AppConfig.h`の`motion`名前空間を変更します。角度の単位は0.1度です。

- 公式推奨範囲: `kOfficialPitchMin = 50`（5°）～`kOfficialPitchMax = 850`（85°）
- 本作品の使用範囲: 5～72°（5°は発話終了時の通常うなずきだけで使用）
- 初期ホーム: 20°
- 睡眠姿勢: 8°
- 横軸の製品範囲: -128～128°、本作品の全動作範囲: -15～15°、現在の待機・音声反応: 正面0°
- 速度のBSP範囲: 0～1000。発話中140、終了時は下降185～215・復帰165～190の低速域を使用（深めの下降は最大200）

上下軸は公式推奨5～85°を絶対範囲とし、上側は従来どおり72°へ制限します。下側5°は発話終了時の深いうなずきだけで使い、低速で650 msかけて下げ、900 msかけて20°へ戻します。`kWorkPitchMin`と`kWorkPitchMax`を公式範囲外にするとコンパイル時チェックまたは実行時クランプで止まります。実機差のホーム較正は、まず工場出荷ファームの設定画面にあるServo Calibrationで正常性を確認してください。本アプリはBSPがNVSから読む較正値を利用しつつ、作品側のホーム角を安全範囲内で指定します。

## 実機テストの順序

1. デバッグ表示でマイク値を確認
2. 正面・画面左・画面右から話し、`DIR`だけを記録して横サーボが連動しないことを確認
3. 静かな部屋でノイズフロアを確認
4. 普通の声で開始・終了判定と「ん？」動作を確認
5. 机を叩き、短い物音が除外されることを確認
6. 待機中と発話開始時に横・上下サーボが動かないことを確認
7. 頭部をゆっくり前後になで、表情と小さな上下動作、2秒後の復帰を確認
8. USB給電で長時間連続動作し、発熱・引っ掛かり・誤反応を確認

詳細は[実機調整ガイド](docs/tuning-guide.md)を参照してください。

## 異常動作時の停止

サーボが引っ掛かる、連続動作する、異音・強い発熱がある場合は、可動部を手で押さえたり無理に回したりしないでください。まず台座側USB-Cケーブルを抜き、電源を切ります。バッテリー動作が続く場合は電源ボタンで停止します。周囲が安全になってから角度・速度を初期値へ戻して再ビルドしてください。原因確認までは再通電しないでください。

## 工場出荷ファームへ戻す

1. PCにM5Burnerをインストールします。
2. M5Burnerを開き、`StackChan`を検索します。
3. `Only Official`を有効にして公式ファームをDownloadします。
4. StackChanを台座側USB-Cで接続し、電源を入れます。
5. ポートが出ない場合はRSTを約3秒長押しし、緑LED点灯後に離します。
6. M5Burnerで`Burn`、対象ポート、`Start`の順に選び、完了までUSBを抜きません。

復元するとこのアプリは上書きされます。公式の最新手順は[StackChan製品ページのRestore Factory Firmware](https://docs.m5stack.com/en/StackChan#restore-factory-firmware)を確認してください。
