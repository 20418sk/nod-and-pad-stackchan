# きいてるﾁｬﾝ 実機調整ガイド

> # 警告: 最初から大きな角度や高い速度へ変更しないでください
>
> 製品版StackChan K151を安定した机に置き、可動部の周囲を空け、原則として台座側USB-Cで給電してください。上下軸は公式推奨の5～85度、横軸は作品側の-15～15度を絶対に超えないでください。引っ掛かり、異音、連続動作、強い発熱があれば、可動部を押さえず台座側USBを抜いて停止します。

調整値は[AppConfig.h](../include/AppConfig.h)にあります。一度に1項目だけ変え、変更前の値を記録してください。以下の順番を飛ばさないでください。

## 0. 準備

- 工場出荷ファームのServo TestとMicrophone Testで、ハードウェア単体が正常なことを先に確認します。
- カスタムファーム書き込みで工場出荷ファームが上書きされることを理解します。
- すぐUSBを抜ける位置に置きます。
- 電源投入前に首を手で回しません。
- 上下範囲5～72度、ホーム20度、睡眠姿勢8度、横範囲-15～15度、正面0度、低速設定を維持します。下限5度は発話終了時の深いうなずきだけで使用します。

## 1. 追尾を発生させずマイク値だけ確認

初回は安全ホーム移動だけを観察し、それ以降はStackChanに触れません。画面を短くタップしてデバッグ表示をONにします。

- 静かなときの`LEVEL`が更新されること
- 声を出すと`LEVEL`が上がること
- 音声を止めると下がること
- 左右の`L`と`R`が別々に更新されること
- シリアルに音声データが出ていないこと

サーボを完全に無動作で測りたい場合は、コードを変更せず、起動時ホーム移動と抑制期間が終わってから値を読みます。安全機構をコメントアウトしないでください。

### 左右マイクの方向診断

1. 正面から同じ短文を3回話し、`DIR:C`または`?`が中心になることを確認します。
2. ごく短く区切って画面左から話し、`DIR:L`が出る傾向だけを記録します。音方向は横サーボへ接続されていません。
3. ごく短く区切って画面右から話し、まず`DIR:R`が複数回出ることを確認します。
4. 左右が逆または不安定でも、現段階では`kSwapStereoChannels`を変更せず記録だけ残します。

`DIR:?`は故障ではなく、相関が弱いか方向ピークが曖昧という安全側の結果です。机の打音や1回だけの結果で左右設定を変えないでください。`DIR`表示によって首が動かないのが現在の正常動作です。

## 2. 静かな部屋のノイズフロアを確認

1. 静かな状態で画面を長押しします。
2. 「しずかにしてね」の約3秒間は話さず、机にも触れません。
3. `NOISE`が`LEVEL`の静音時中心に近いことを確認します。
4. `START THRESHOLD`が`NOISE`より十分高いことを確認します。

`NOISE`が異常に高い場合は、エアコン、PCファン、机の振動、USBケーブルの接触を確認して再較正します。

## 3. 普通の声で開始・終了判定を確認

StackChanから普段の会話距離で話します。

1. 声を出して約120 ms後に`SPEECH_CAND`から`LISTENING`へ進むことを確認します。
2. `LISTENING`へ入る瞬間に傾聴顔となり、横・上下サーボは動かないことを確認します。
3. 話の途中で0.2～0.4秒だけ間を空け、まだ終了しないことを確認します。
4. 話し終えて約600 ms後に`REACTING`へ進むことを確認します。

反応が鈍い場合は`audio::kStartThresholdRatio`を0.1ずつ下げます。誤反応が多い場合は0.1ずつ上げます。`kStartThresholdMargin`は20程度ずつ調整します。

## 4. 机を叩く音で反応しすぎないか確認

StackChan本体を叩かず、机の離れた位置を軽く1回叩きます。

- 一瞬`SPEECH_CAND`になっても、120 ms未満なら`IDLE`へ戻ること
- `REACTING`にならないこと

反応する場合は、まず設置面へ柔らかい滑り止めを置きます。次に`listener::kSpeechStartHoldMs`を20 msずつ、または`kMinimumSpeechMs`を50 msずつ増やします。普通の短い返事まで失わないか再確認します。

## 5. 正面待機と小さなうなずきを確認

この段階まで角度を増やさないでください。静かな状態で待ち、横0度・上下20度のまま勝手に動かないことを確認します。普通の声で話し、傾聴中の浅いうなずきと、発話終了後に安全範囲内のランダムうなずきが出ることを確認します。音方向表示に横軸が連動してはいけません。

- 上下軸が引っ掛からない
- 待機中と発話開始時に横・上下サーボが動かない
- 音方向表示が変わっても横軸が正面0度を維持する
- 下向きからホームへ滑らかに戻る
- うなずき等の反応後、横軸が低速で正面0度へ戻る
- 停止後にモーターがうなり続けない
- 本体・サーボが急に熱くならない

方向が期待と逆、またはホームが不自然なら、先にM5Burnerで工場出荷ファームへ戻してServo Calibrationを確認します。本アプリ内の角度を大きくして補正しないでください。

## 6. サーボ音抑制期間を確認

うなずき、なでなで、睡眠姿勢の動作中と直後を見ます。サーボ音だけで新しい`SPEECH_CAND`や`LISTENING`へ入らないことを確認します。待機中と発話開始時には抑制期間が発生しないのが正常です。

うなずきや睡眠姿勢で自己反応する場合は`motion::kServoSoundSuppressionAfterMs`を少しずつ増やします。長くしすぎると、人の発話を聞き逃します。最小限にします。

### 頭部なでなでの確認

音声との統合前に、頭部上面を前→後、後→前の両方向へゆっくりなぞります。スワイプ時はHappy表情・大きさを変えず小さく上下する1個のハート・左右3本ずつの照れ頬と小さな上向き動作が出ます。頭部のどこかへ40～400 msだけ触れて完全に離した時は、ハートが最初に一度だけ大きく弾み、サーボは動かないのが正常です。長押しでは単発タップ反応が出ないこと、短い接触中に隣接2ゾーンを順に通った場合はスワイプが優先されることも確認してください。どちらも手を離して約2秒後に元へ戻ります。

単発タップとなでなでの両方で、最初の接触音が`SPEECH_CAND`や`LISTENING`へ入らないことを確認します。最後の接触・リリースから900 msは人の声も意図的に無視するため、解除後に普通の声で反応が再開することも確認してください。

なでなで中にサーボがすでに動いている場合は、公式実装と同様に新しいサーボ命令を重ねず表情だけ反応します。`motion::kHeadPetRise`を最初から増やしてはいけません。初期値7度のまま、引っ掛かり・異音・発熱がないことを確認します。

## 7. 音声検出とサーボを統合

次を順に試します。

1. 発話中: 約1.6秒間隔で20→16.8→20度の浅いうなずき
2. 0.2秒以上の発話終了: 1～2回、最下点5～13度の範囲で変化すること
3. 複数回話し、回数・深さ・速さが少しずつ変わること
4. 反応直後に再度話す: 連続うなずきが抑えられる
5. 60秒静かにする: 寝顔と寝姿勢
6. 寝姿勢で話す: 通常顔と安全ホームへ戻る

机の打音だけでは開始保持と最小発話時間を満たさないことも確認します。シリアルの`回数`、`最下点`、下降/復帰`速度`で実際の計画を確認できます。最初の実機確認では可動部の周囲を空け、5度付近で引っ掛かり、異音、うなりがあれば直ちに電源を抜いてください。

## 8. 長時間連続動作を確認

台座側USB給電で、最初は10分、次に30分、最後に想定展示時間の順で延ばします。

- サーボの温度、うなり、ホームずれ
- エアコンなど定常音によるノイズフロア変化
- 長い無音後の誤反応
- 連続会話時の最低反応間隔
- 画面ちらつき
- 待機中と発話開始時にサーボが動かず、短い声を取りこぼさないこと
- 音方向表示が変わっても横軸が正面を維持すること
- タッチ長押し較正
- 隣接2ゾーンを順に通る両方向のなでなで、短い2回トントン、2秒後の復帰
- なでなで直後のサーボ音を発話と誤認しないこと
- シリアルのマイク/サーボエラー

異常が1回でもあれば通電時間を延ばさず、ログと設定値を記録して停止します。

## 変更後の再検証

`AppConfig.h`を変更したら、必ず次を実行します。

```powershell
pio test -e native
pio run -e stackchan_k151
```

ビルド時に上下または横軸安全範囲の`static_assert`が失敗した場合は、範囲を広げず設定を作品側の安全範囲内へ戻してください。
