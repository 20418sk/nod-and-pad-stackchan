# Nodding StackChan 実機調整ガイド

> 最初から大きな角度や高い速度へ変更しないでください。製品版StackChan K151を安定した机に置き、可動部の周囲を空け、原則として台座側USB-Cで給電します。引っ掛かり、異音、連続動作、強い発熱があれば、可動部を押さえずUSBを抜いて停止してください。

調整値は[AppConfig.h](../include/AppConfig.h)にあります。一度に1項目だけ変更し、順番に確認します。

## 0. 準備

- 工場出荷ファームのServo TestとMicrophone Testでハードウェアを確認
- 上下5～72°、ホーム20°、睡眠8°、横±15°、正面0°を維持
- 電源投入前に首を手で回さない
- すぐUSBを抜ける場所に置く

## 1. 起動とホーム

電源投入時だけ、上下20°・横0°への低速移動が起きます。到達後はトルクが解放され、サーボ音抑制が終わってから約1.5秒のマイク較正が始まります。

- エラー顔や赤LEDが出ない
- 横0°、上下20°が不自然でない
- 停止後にサーボがうなり続けない

不自然な場合はアプリ内の角度で無理に補正せず、工場出荷ファームのServo Calibrationを確認します。

## 2. マイクと方向表示

画面を短くタップしてデバッグ表示をONにします。

- 静音時より声を出した時の`LEVEL`が高い
- 左右の`L`と`R`が別々に更新される
- 正面・画面左・画面右で`DIR:C/L/R`の傾向が見える
- 不確かな時に`DIR:?`になる
- `DIR`が変化しても横サーボは正面のまま

左右方向は診断値です。逆または不安定でも、少数回の結果だけで`kSwapStereoChannels`を変えないでください。

## 3. ノイズ較正

静かな状態で画面を約1.2秒長押しし、「しずかにしてね」の約3秒間は話さず、机にも触れません。`NOISE`が静音時の`LEVEL`付近になり、開始しきい値がそれより十分高いことを確認します。

ノイズが高い場合はエアコン、PCファン、机の振動、USBケーブルの接触を確認して再較正します。

## 4. 発話判定

普段の会話距離で話します。

1. 約120 ms後に`SPEECH_CAND`から`LISTENING`へ進む
2. 傾聴顔になり、発話開始そのものではサーボが動かない
3. 発話中は約1.6秒間隔で浅くうなずく
4. 0.2～0.4秒の間では発話終了にならない
5. 話し終えて約600 ms後にランダムうなずきが始まる
6. 最後は上下20°へ戻る

感度が低い場合は`audio::kStartThresholdRatio`を0.1ずつ下げます。誤反応が多い場合は0.1ずつ上げます。机の一打で反応する場合は、設置面を柔らかくした後、`listener::kSpeechStartHoldMs`を20 msずつ、または`kMinimumSpeechMs`を50 msずつ増やします。

## 5. うなずき

- 発話中: 20° → 16.8° → 20°
- 発話終了: 1～2回、最下点5～13°
- 深い5～7°は1回だけ
- 下降速度185～215、復帰速度165～190
- 同じ動作が機械的に連続しない
- 反応中と直後のサーボ音で新しい発話が始まらない

5°付近で引っ掛かり、異音、うなりがあれば直ちに停止します。安全制限や起動時の到達確認をコメントアウトしてはいけません。

## 6. 頭部タッチ

前→中央、中央→後、逆方向も含めて隣接2ゾーンをなでます。Happy表情、1個のハート、左右3本の照れ頬、桃色LED、小さな上向き動作を確認します。

頭部のどこかへ40～400 ms触れて完全に離すと、同じ表情とハートになりますがサーボは動きません。長押しは単発タッチにしません。どちらも手を離して約2秒後に戻ります。

接触中とリリース後900 msは声も意図的に無視します。接触音を発話扱いせず、抑制終了後に普通の声へ反応することを確認します。

## 7. 睡眠

60秒静かにして、上下8°の寝姿勢と`Z`の1→2→3個表示を確認します。声を出すと通常顔へ戻り、安全ホームへ移動します。起床移動中のサーボ音で再反応しないことも確認します。

## 8. 長時間試験

台座側USB給電で10分、30分、想定展示時間の順に延ばします。

- サーボの温度、うなり、ホームずれ
- 定常音によるノイズフロア変化
- 長い無音後の誤反応
- 画面ちらつき
- タッチ後の誤発話
- 横サーボが音方向へ動かないこと

異常が1回でもあれば時間を延ばさず、ログと設定値を記録して停止します。

## 変更後の確認

```powershell
pio test -e native
pio run -e stackchan_k151
```

nativeテストにはPC側のGCC/G++が必要です。角度の`static_assert`が失敗した場合は範囲を広げず、安全範囲内へ戻します。実機への書き込みは、ビルドと差分確認が完了した後に人が明示的に行います。
